### Why Do We Need This?

As far as I can tell, every other crate that does unit systems defines some amount of the the types you will use, or has macros do it, or relies on direct method calls instead of traits, this means:
- You can't choose the memory layout, or naming. A breaking library change is a breaking change for you too.
- The crate probably only supports limited number types, or has tons of flags for enabling each specific third party type.
- You often can't `#[derive()]` or `impl` your own traits (orphan rule!), so you end up with tons of flags for enabling each third party trait.
- You may have to learn a special DSL, which may not support controlling `pub` or or adding extra fields (none that I've seen) or doc comments.
- If it has a macro to generate everything at once, chances are that the things it generates are hardcoded to work with eachother without traits.
- It's unclear what types get generated, where they are, what they're named.
- It may be hard to extend as you please - E.G. integrating dynamic units/ unit types in a UI. The traits may have prohibitively complex generics.

Crates like `serde` and `clap` let you define your own types and customize in depth how the derive macros generate standard traits, and I wanted this for dimensional analysis too. Reflection solves some, but not all these problems.

### The Idea

yadc is **patterns and a code generator**: no traits, no types. A unit system is a crate of yours, generated once from a TOML file and then yours to read, edit and extend, where code reads like dimensional algebra on a whiteboard:

- **You own every type.** The unit type, the quantity type, the dynamic quantity, every unit and every quantity alias: all declared in your crate, with your names, your `pub`, your doc comments, your extra derives. Nothing in it is a yadc type.
- **Units are in the type.** A quantity is a number and its unit: `SIQuantity<U, N, B>(N)`, the unit `U` a const parameter. `2.0 * KILOMETRE` is a number of kilometres; `.into()` converts it into the base unit its target type names. Base units multiply into base units, so `mass * acceleration` is a `Force` with no conversion at all; any other unit multiplies into a unit that is not a base unit (`KILO * METRE` is the kilometre, `KILOMETRE / HOUR` km/h).
- **Standard traits only.** Quantities talk through `+ - * /`, `From`, `TryFrom`, `PartialOrd` and `Display`. The unit type's own std operators return an `Option` (`None` where two units don't combine), and [`const_derive_more`](const_derive_more/)'s `#[derive(ConstOps)]` lifts them onto the quantity: an operator exists exactly where the units' operator gives `Some`.
- **Modelling choices are yours.** Is angle a base unit? Is mass based on the gram or the kilogram? Which units have names? That is data in *your* TOML. [`yadc-si`](yadc-si/) is one such system, generated from [`yadc-codegen/si.toml`](yadc-codegen/si.toml); [`yadc-ucum`](yadc-ucum/) another, generated from the UCUM tables.
- **Nothing hidden.** The generated crate is ordinary Rust, laid out by `rustfmt`: what you read is what compiles.

### The Whiteboard Principle

**Every operation is one you could write on a whiteboard.** A quantity in kilometres times a quantity in hours is a quantity in km·h; a length plus a time is nothing, so it doesn't compile; 25 °C is a temperature you convert before you multiply it, because "twice 25 °C" depends on where the zero is.

- **Numbers only through units.** A number becomes a quantity by multiplying a unit (`2.0 * KILOMETRE`), and leaves one as a plain ratio, divided by a unit: `f64::from(d / KILOMETRE)`. A quantity's field is private to the crate that defines it.
- **Partial operations return `Option`.** Statically, a refused operator doesn't compile; on a quantity whose unit is known only at run time, the same operators return `Option`, so a calculation reads `((a * b)? + c)?`.
- **Exact definitions.** A unit's size and zero are an `Exact` (`num/den · 10ⁿ · πᵏ`), rounded once, to the number type in use, by std `From`.

### Quick Start

A crate using a generated system needs `#![feature(generic_const_exprs)]`, plus `const_trait_impl` and `const_ops` to compute in `const` items:

```rust
#![feature(generic_const_exprs, const_trait_impl, const_ops)]
#![allow(incomplete_features)]

use yadc_si::dynamic::DynamicSIQuantity;
use yadc_si::dynamic::mechanical::LengthUnit;
use yadc_si::mechanical::*;
use yadc_si::thermal::*;
use yadc_si::*;

// A unit is a constant, one of it; a quotient of two is a unit too.
const KMH: SIQuantity<{ KILOMETRE.unit().times(HOUR.unit(), -1) }, Exact, NOT_BASE> = KILOMETRE / HOUR;

// A number times a unit is a quantity of that unit; `.into()` converts
// it into the base unit the annotated type names.
let d: Length<f64> = (2.0_f64 * KILOMETRE).into();     // 2000 m
let t: Time<f64> = 100.0 * SECOND;                       // already a base unit
let v: Velocity<f64> = d / t;                            // 20 m/s
let m: Mass<f64> = 70.0 * KILOGRAM;
let a: Acceleration<f64> = v / t;
let f: Force<f64> = m * a;                               // 14 N
// let nope = d + t;                                     // error: cannot add: `+` of these parameters has no result

// A number leaves as a plain ratio: divide by a unit.
let metres = f64::from(d / METRE);                       // 2000.0
let km = f64::from(d / KILOMETRE);                       // 2.0
let hz: Frequency<f64> = 1.0 / t;                        // 0.01 Hz

// Units with a zero or a log scale convert; they have no products.
let temp: ThermodynamicTemperature<f64> = (25.0_f64 * CELSIUS).into(); // 298.15 K
let p: Power<f64> = (30.0_f64 * DECIBEL_MILLIWATT).into();             // 1 W

// Into a unit other than a base unit: name it in the type.
let speed: SIQuantity<{ KMH.unit() }, f64, NOT_BASE> = v.into();      // 72 km/h
let kmh = f64::from(speed / KMH);                                       // 72.0

// A prefix is a scale: prefixes multiply into one, so a unit has one form.
assert_eq!(KILO * METRE, KILOMETRE);
assert_eq!((KILOMETRE / METRE).unit(), KILO.unit());
let fast = 2.0_f64 * KILOMETRE / SECOND;                 // 2 km/s
println!("{:e}", 0.002_f64 * KILOGRAM);                   // 2 g: the best SI prefix

// A unit chosen at run time: every operator returns an Option.
let q = (DynamicSIQuantity::from(d) / DynamicSIQuantity::from(t)).unwrap();
let back: Velocity<f64> = q.try_into().unwrap();
assert_eq!(DynamicSIQuantity::from(d) + DynamicSIQuantity::from(t), None);

// A choice among a quantity's units, printed and parsed by its symbol.
let unit: LengthUnit = "km".parse().unwrap();
let n = SIUnit::from(unit).from_base(metres);            // 2.0
```

### What a System Crate Holds

[`yadc-codegen`](yadc-codegen/) writes these from a TOML file (see its README for the format):

- **The unit type**, `SIUnit`: a product of named units to integer powers. Base units (`[dim]`) define the dimensions; every other named unit is a size times other units (the hour is 3600 s). A prefix is a scale: every prefix of a product multiplies into the unit's one exact scale, so a unit has one form however it is built (`KILO * KILO` is `MEGA`, `KILOMETRE * MILLIMETRE` is `METRE * METRE`), and a prefixed unit of the TOML is that product (`KILOMETRE` is `KILO * METRE`). `Display` writes the scale as a prefix (`km^2`, `kPa`, `mg`); a quantity's `{:e}` picks the SI prefix that puts the number in [1, 1000). A unit of a single named unit may count from a zero (°C: 1 K from 273.15 K) or on a log scale (dBm: `0.001 · 10^(n / 10)` W); such a unit has no products. Its std `* / + -` return `Option`.
- **`Exact`**, the exact number unit sizes are written in, with std `From` to `f64`, `f32` and every primitive integer.
- **The quantity**, `SIQuantity<U, N, B>(N)` with `#[derive(const_derive_more::ConstOps)]`: `B`, a `Base`, says whether `U` is a base unit or a product of base units (`BASE`) or not (`NOT_BASE`); a product is `BASE` where both factors are. Quantities of one unit add and compare; a product is counted in the product of the units. A quantity of a plain number is a number of each primitive type, scaled by its unit's size (`f64::from(d / KILOMETRE)`).
- **Unit constants**, one of each unit, counted in `Exact`: the prefixes and base units at the crate root (`KILO`, `METRE`), the rest in their family's module (`mechanical::KILOMETRE`).
- **Quantity aliases**, `Length<N, U = metre, B = BASE>`: a quantity's base unit by default, any unit of it when named.
- **Two blanket `From` impls**: a quantity of any unit into a base unit of the same dimension, and back. The target type picks the unit.
- **Unit enums**, `dynamic::mechanical::LengthUnit`: a run-time choice among a quantity's units, with `Display`, `FromStr` and `From<LengthUnit> for SIUnit` (`const_derive_more`'s `Values`).
- **The dynamic quantity**, `DynamicSIQuantity { unit, is_base, value }` (`const_derive_more`'s `Dynamic`): `From` any `SIQuantity<U, f64, B>`, `TryFrom` back, every operator returning `Option`.

### Defining Your Own System

Write a TOML file and run the generator (`cargo run -p yadc-codegen -- my.toml -o my-units`), or write the pattern by hand. Its core is a unit type with `Option`-returning std operators and a quantity struct deriving `ConstOps`:

```rust
#![feature(generic_const_exprs, adt_const_params, const_trait_impl, const_ops, const_cmp)]
#![feature(derive_const, const_destruct, const_convert)]
#![allow(incomplete_features)]

use core::marker::ConstParamTy;
use core::ops::{Add, Div, Mul, Sub};

/// The unit: metres and seconds to integer powers.
#[derive_const(PartialEq)]
#[derive(Copy, Clone, Debug, Eq, ConstParamTy)]
pub struct Unit { pub m: i8, pub s: i8 }

// The unit's own algebra, std operators returning `Option`: `None` where
// two units do not combine.
const impl Mul for Unit {
    type Output = Option<Unit>;
    fn mul(self, o: Unit) -> Option<Unit> { Some(Unit { m: self.m + o.m, s: self.s + o.s }) }
}
const impl Div for Unit {
    type Output = Option<Unit>;
    fn div(self, o: Unit) -> Option<Unit> { Some(Unit { m: self.m - o.m, s: self.s - o.s }) }
}
const impl Add for Unit {
    type Output = Option<Unit>;
    fn add(self, o: Unit) -> Option<Unit> { if self == o { Some(self) } else { None } }
}
const impl Sub for Unit {
    type Output = Option<Unit>;
    fn sub(self, o: Unit) -> Option<Unit> { if self == o { Some(self) } else { None } }
}

/// A quantity: a number of `U`. `ConstOps` lifts the operators of the
/// number and of the unit onto it.
#[derive(Copy, Clone, PartialEq, PartialOrd, Debug, const_derive_more::ConstOps)]
pub struct Qty<#[ops(one = Unit { m: 0, s: 0 })] const U: Unit, N>(N);

pub type Length<N> = Qty<{ Unit { m: 1, s: 0 } }, N>;
pub type Time<N> = Qty<{ Unit { m: 0, s: 1 } }, N>;
pub type Velocity<N> = Qty<{ Unit { m: 1, s: -1 } }, N>;

pub const METRE: Length<f64> = Qty(1.0);
pub const SECOND: Time<f64> = Qty(1.0);

/// A plain number is its number.
impl From<Qty<{ Unit { m: 0, s: 0 } }, f64>> for f64 {
    fn from(q: Qty<{ Unit { m: 0, s: 0 } }, f64>) -> f64 { q.0 }
}

fn main() {
    let d = 100.0 * METRE;
    let t = 9.58 * SECOND;
    let v: Velocity<f64> = d / t;
    // let nope = d + t;  // error: cannot add: `+` of these parameters has no result
    println!("{:.2} m/s", f64::from(v / (METRE / SECOND)));
}
```

Add any derives you like (`serde`, `JsonSchema`, `Reflect`, ...): the types are yours, so the orphan rule never gets in the way.

### Column Explanations

Apologies if I've got some of these columns wrong.

- **Active** — updated within the last two years (checked May 2026). ✗ does not mean unusable - it's not like unit systems change much.
- **`no_std`** — can be used without the Rust standard library (e.g. on embedded targets).
- **Own types** — you define all the involved types in your own crate; the library only provides derives or a code generator. ✗ means the library defines the struct and you depend on it directly, or macros define it for you.
- **Dim Vector** — multiplying two quantities automatically produces the correct output type without you manually registering the relationship. E.g. `mass * accel` gives you a force-typed value purely from the dimension exponent arithmetic. ✗ means you must define each quantity and its operations by hand, or use explicit algebraic derivation macros.
- **Stores In Base Units** — the stored value is a raw number in canonical base units; the unit plays no role in storage. ✗ means either the unit is baked into the value's scale (so `5 km` stores `5.0`, not `5000.0`) or a unit tag is packed alongside the value at runtime.
- **Custom Value Type** — the underlying numeric type is customizable, so you can use `f32`, `i64`, `Vector3<f32>`, or any custom type. ✗ means the library is hardwired to one type. "fixed list" means the library supports only certain types it has added support for.
- **Angles/Absolute** — the type system distinguishes angle quantities from plain dimensionless ratios, and distinguishes absolute temperatures from temperature intervals, so `T − T = ΔT` and `ΔT + T` is a compile error. (yadc-si counts radians on an exponent axis; °C is a unit with a zero, converted into kelvin before any product.)
- **UCUM Serde** — whether the serde wire format uses [UCUM](https://ucum.org) unit strings. `dim` means the quantity's *dimension* is expressed as a UCUM base-unit composition (e.g. `m.kg.s-2`), with the stored value always in base units. `unit` means the specific *storage unit* is expressed as a UCUM string (value may not be in base units). `dimensioned`'s UCUM feature is a compile-time unit system of UCUM-named constants, not a serde format.
- **Full SI Coverage** — ships with a complete, ready-to-use SI implementation covering all ISQ quantities and units.
- **Static** — dimensions are checked at compile time; a wrong-dimension operation fails to compile.
- **Dynamic** — dimensions are checked at runtime; a mismatched-dim operation is reported as an `Option` / `Result` (in yadc-si: every operator of `DynamicSIQuantity` returns an `Option`, `None` where there is no result, chained with `?`).
- **Fully Trait Based** — the library exposes public traits (`Quantity`, `Unit`, …) as abstraction boundaries so you can write functions that are generic over *any* conforming quantity type — including quantities from unit systems the library has never seen. ✗ means the library provides only concrete types (even if parameterized); a function written against those types is always tied to one unit system.

### Nightly features required

Up front, this is a pretty experimental crate and relies on a bunch of fairly unstable nightly features, the goal is 'no compromise, with what nightly has'.

| What your crate does | Required at crate root |
|---|---|
| Uses a generated system's quantities and units (`Length<f64>`, `2.0 * KILOMETRE`, `.into()`) | `generic_const_exprs` |
| … and computes in `const` items (`const KMH: … = KILOMETRE / HOUR;`) | additionally `const_trait_impl`, `const_ops` |
| Defines a system: a unit type and a quantity deriving `ConstOps` | `generic_const_exprs`, `adt_const_params`, `const_trait_impl`, `const_ops`, `const_cmp`, `const_destruct`, `const_convert`, `derive_const` |
| … with `&'static str`s in the unit type (as the generated `SIUnit`) | additionally `unsized_const_params` |
| Uses `const_derive_more`'s other derives | see [`const_derive_more`](const_derive_more/src/lib.rs) |

Plus `#![allow(incomplete_features)]` to silence the `generic_const_exprs` warning.

- **`generic_const_exprs`** — needed wherever a value's *type* involves a const expression, e.g. `SIQuantity<{ A * B }, N, BASE>` (the `Output` of `Mass * Acceleration`). Every consumer trips this the moment they write `mass * accel`.
- **`adt_const_params`**, **`unsized_const_params`** — a const parameter whose type is a struct of yours (`const U: SIUnit`), holding `&'static str`s.
- **`const_trait_impl`**, **`const_ops`**, **`const_convert`** — `ConstOps` writes `const impl`s of core's operators and `From`, and the unit type's operators are `const impl`s, so the unit algebra runs inside const-generic bounds and quantities compute in `const` items.
- **`const_cmp`**, **`derive_const`** — `#[derive_const(PartialEq)]` on the unit type, so `==` on units is const-callable.
- **`const_destruct`** — lets a `const` operator drop a generic number it knows nothing about.
